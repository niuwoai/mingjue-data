# 历史工具调用数据盘点

日期：2026-10-20  
文档版本：1.0.0  
范围：本机可读的 WillDeep、Claude Code、Codex 会话文件。仅本地只读统计；没有重放命令，没有向外部模型发送内容，也没有导出会话正文或工具参数。

## 1. 结论

各来源内部按调用 ID 去重后，工具调用记录合计 **665,534 条，约 66.55 万条**。补充交叉扫描发现 WillDeep 来源之间存在重复；Claude Code、Codex 与其他来源之间未做完整交叉去重，不能称为全局唯一执行次数。

这些是历史调用请求，不保证每次执行成功或造成了实际副作用。内容重复、命令近重复、同任务变体尚未剔除，全部未经安全标签审核，不能直接当作同等数量的训练金标。

对于工具调用风险判断实验，当前更需要解决的是上下文还原、授权判断、类别覆盖和标注质量，现有调用量足以开始抽样验证；危险样本数量仍未知。

WillDeep 补充扫描的内部交叉重复：CLI 与主应用 127 个 ID，主应用与子代理 5 个 ID，CLI 与子代理 0 个 ID。三者联合观察到 **28,048 个调用 ID**。补充扫描晚于上表，其中有活跃记录新增，因此不能将这个联合数与上表分项精确相减核对。

统计期间文件可能继续写入，各来源快照时刻略有不同。本报告给出盘点规模，不作为稳定不变的账本。

## 4. 本机来源与统计方法

| 来源 | 路径 | 扫描文件与格式 |
| --- | --- | --- |
| WillDeep CLI | `~/.willdeep/sessions` | 175 个 JSON 文件 |
| WillDeep 主应用 | `~/Library/Application Support/WillDeep/agent-sessions` | 1,079 个 JSON 文件；仅识别有 messages 的会话对象，不把全部 JSON 都当会话 |
| WillDeep 子代理 | `~/Library/Application Support/WillDeep/subagent-transcripts` | 207 个 JSON 文件 |
| Claude Code | `~/.claude/projects` | 1,129 个 JSONL 文件，包含子代理记录 |
| Codex | `~/.codex/sessions`、`~/.codex/archived_sessions` | 合计 3,730 个 JSONL/JSONL.ZST 文件，含 4 个空文件 |

WillDeep 按 `tool_calls` / `toolCalls` 记录调用，以 `id` / `externalID` 去重。Claude Code 按消息内容中的 `tool_use` 统计，以工具调用 ID 去重。Codex 解压读取归档，仅统计 `response_item` 的 `function_call` 和 `custom_tool_call`，排除 event 镜像及压缩替换历史，避免重计。

工具结果通过对应调用 ID 关联，只统计能否找到结果，不检查结果正文的正确性。返回错误、拒绝或空输出仍可能存在返回记录。

Codex 采用只解析调用与会话元数据记录的定向扫描完成统计，目标记录未遇到 JSON 解析错误；不能据此宣称其他所有日志类型均已做格式审计。其他来源扫描未记录解析或读取错误。

Claude Code 可见记录时间范围为 2026-06-16 至 2026-10-15（北京时间）；Codex 识别到的会话元数据时间范围为 2026-06-30 至 2026-10-20（北京时间）。这是各自本机存量范围，不是产品首次使用日期。

## 5. 不能从本次盘点直接得出的结论

- 不能判断危险、越权、正常调用各有多少；没有开展风险标注。
- 不能证明所有调用都保留了完整用户意图、授权范围、cwd、环境与可信来源标记。
- 不能把成功退出、无投诉或有返回记录当作安全金标。
- 不能把同会话反复尝试或同模板大量复制当作独立任务组。
- 不覆盖其他机器、已删除记录、未扫描备份，以及 ChatGPT 网页/云端未同步到本地的历史。本次 Codex 是本地产品会话记录，不代表完整 ChatGPT 云端历史。
- 不承诺读取所有嵌套编排后，条目数会等于实际工具执行次数。

## 6. 建议下一步：先审计样本可用率，再批量标注

1. 从 Shell 候选中分层抽取约 1,000～2,000 条：按来源、月份、命令族、项目和会话组采样，控制重复模板。
2. 对每条尝试还原执行前状态：用户任务、明确授权、命令、cwd、目标路径、生产/测试环境、必要前序工具信息。缺失字段明确标记 unknown，不靠教师补编。
3. 先人工核查 200～300 条，估算上下文完整率、正常/危险/不确定比例及单条标注耗时，冻结规则。
4. 在确认数据外发范围并完成脱敏后，再调用实际可用的 GPT/Opus 强模型做训练池预标注；记录真实模型 ID 和提示词版本。
5. 分歧、高风险放行和边界案例人工裁决；锁定测试使用独立人工金标。
6. 同一历史会话及其派生变体按组切分，安全案例与危险案例成对保留；先形成小规模可审计数据集，再扩大训练。

以上是后续建议，本轮没有执行内容导出、教师调用或标注作业。
