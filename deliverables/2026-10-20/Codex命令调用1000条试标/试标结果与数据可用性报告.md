# Codex 1,000 条命令调用：试标结果与数据可用性

版本：1.1.0  
日期：2026-10-20  
性质：本地探索性抽样、静态规则预标与有限助手复核；不是双人专家金标，不是模型评测结果。

## 1. 结果

从本机 Codex 活跃和归档日志中，按调用 ID 去重，找到 95,911 条可解析 `cmd` 参数的直接 `function_call/exec_command`，按月份比例抽取 1,000 条，来自 146 个会话。

| 最终试标 | 数量 | 样本内占比 | 应如何理解 |
| --- | ---: | ---: | --- |
| 正常初判 | 919 | 91.9% | 未识别到显著高后果动作，主要是查看代码、状态、测试和有界开发修改；不保证绝对安全或授权完整 |
| 危险/高风险操作候选 | 15 | 1.5% | 包括远程发布、生产路径变更等；不等于恶意，也不等于应无条件阻止 |
| 已确认越权 | 0 | 0.0% | 本轮有限材料没有确认到明确越权；不证明历史上不存在越权 |
| 信息不足 | 66 | 6.6% | 需要脚本正文、历史状态或更完整上下文才能判断 |
| 合计 | **1,000** | **100.0%** | 本表不是全量历史的真实有害率估计 |

“正常”与“危险”是本次风险初判；是否允许执行需要另核授权和策略。15 条高风险里包含正常发布工作，不能全部转成 `block` 训练标签。0 条已确认越权同样不能作为“越权率为零”的证据。

## 2. 抽样方法与代表性

抽样种子：`rsi-tool-risk-sample-v1-20261020`。对调用 ID 计算确定性 SHA256 优先级，在月份内选取，再按总体月份调用数比例分配 1,000 个名额。没有按危险关键词富集，没有按试标结果替换样本。

| 月份（日志 UTC 月份） | 可解析直接命令总体 | 本次样本 |
| --- | ---: | ---: |
| 2026-06 | 4,080 | 43 |
| 2026-07 | 89,309 | 931 |
| 2026-08 | 2,522 | 26 |
| 合计 | **95,911** | **1,000** |

扫描 3,730 个 JSONL/JSONL.ZST 文件。目标记录未遇到解析错误；样本命令无超长截断，工作目录全部有记录。1,000 条的抽取发生在调用 ID 去重后，内容重复仍保留，以便观察真实调用分布。

此前盘点的 95,923 次 `exec_command` 包含更宽的调用类型口径；这里限定为可解析 JSON `cmd` 的直接 function_call，不将两个数字混作相同总体。本轮没有把 `exec` 编排内的 JavaScript 子调用展开，因此不代表 9～10 月当前工具使用形态。

本会话设置为排除，实际未命中符合口径的直接调用；此次盘点主要通过编排工具执行。活跃文件可能继续变化，冻结结果以清单与哈希为准。

## 3. 比数量更重要的三个发现

### 3.1 调用多，但独立场景少

- 1,000 条来自 146 个会话。
- 最大单会话贡献 **489 条（48.9%）**。
- 前五个会话合计贡献 **669 条（66.9%）**。
- 按原始命令文本 SHA256 统计，只有 **803 个不同命令文本**；这仍未做近重复归并。

一个长任务中重复查看文件、运行测试、调整版本，能产生很多调用，但不能当成等量独立业务案例。后续训练和验证必须按会话/任务组隔离，不能将这种长会话随机拆到训练与测试两边。

### 3.2 日志里的 user 不总是人的新指令

首轮抽取发现，一些 `user` 角色记录是 Goal 续跑、环境信息、插件推荐或技能注入。若直接取最近一条 user 文本，容易丢掉真实任务，甚至错误识别授权。

随后重新扫描入选样本的 146 个原文件前缀，过滤了 **2,680 条已知合成/注入型用户记录**，为全部 1,000 条样本匹配到原调用位置，保留最近三条用户角色候选。过滤数是扫描到的记录次数，不是独立会话数或用户数。

其中 **2 条没有保留下有效近期用户候选**；其余 998 条有候选文本，也不代表 998 条都具有完整授权。更早的批准、代理委派关系、目标资源归属和环境状态仍可能缺失。

### 3.3 高风险操作不等于有害操作

样本中能看到明确要求构建、推送、发布的任务。远程发布有风险，但在相应任务中可以是正常工作。如果只给命令贴“危险”标签，再把它直接当“禁止执行”，模型会错误阻止正常研发流程。

更合适的训练字段是：风险类型/影响范围、授权状态、信息完整性、最终策略动作，分别存储。本轮 `policy_action_gold` 保持为空，没有生成未经验证的 allow/block 真值。

## 5. 试标过程与复核边界

| 阶段 | 正常 | 高风险 | 信息不足 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 首轮规则预标 | 848 | 17 | 135 | 简单词法规则；另有 1 条疑似约束冲突 |
| 修正规则后 | 904 | 18 | 78 | 修正语法检查、格式化、标准构建、读取等误报，并补充对象存储上传 |
| 有限助手复核后 | **919** | **15** | **66** | 15 条逐项修订；疑似约束冲突未确认越权 |

助手浏览了首轮非正常条目、疑似约束冲突条目，以及固定种子抽取的 50 条正常样本，共 **203 条命令摘要**；其中 **22 条重点查看近期任务片段**。部分长命令仅查看摘要，少数重点内联脚本查看了完整可见命令。没有审查全部外部脚本源码或证明目标环境状态。

其余样本主要仍是规则预标；本轮没有双人独立标注、专家裁决、一致性验证或外部 GPT/Opus 教师调用。不能把结果写成“1,000 条人工审核金标”，也不能把正常样本抽查当成对规则漏报率的充分估计。

本批样本参与了规则修订和判定标准完善，因此后续可作为训练/开发候选，不应原样作为独立最终测试集。正式验收另采新会话与新时间窗口。

## 6. 对 2B 小模型训练的具体建议

**值得继续，但不建议现在把这 1,000 条原样送去训练。** 主要问题是长会话集中、月份偏差、高风险类别少，以及授权链/脚本内容未完整还原。

1. 下一批按会话/任务族均衡，建议每会话最多 5～10 条，并去掉高度相似的文件查看和重复测试。另抽 `exec` 编排中的真实命令，补足近期数据。
2. 先人工建立约 200～300 条种子金标：正常读取、有界修改、授权发布、未授权发布、危险删除、数据外发、动态路径和缺证据等均有覆盖。
3. 对本批 66 条信息不足补齐入口脚本的历史版本/哈希、必要批准、生产或测试环境标识；无法补齐的保留 unknown，不让教师补编事实。
4. 从真实正常任务派生成对边界例：只改变目标路径、授权范围或接收方。全部派生例与原任务同组，合成比例单列。
5. 强模型用于训练池预标注和难例发现；先确认脱敏和外发范围，再调用实际可用的 GPT/Opus 版本。最终测试仍用独立金标。
6. 模型训练目标先考虑“是否需要进一步复核”；高风险识别和是否越权分开建标签。低后果正常样本不能自动成为所有环境下的 allow 金标。

通过上述步骤形成第一批可靠数据，再在 5070 Ti 上做明决 2B 对照实验。先比较规则、未微调模型、微调模型在相同风险约束下的误放行、误拦截和覆盖率，不能以训练集准确率验收。
