## 一句话结论

**五条预注册门槛 1 过 4 失败，`all_gates_passed=false`，`production_qualified=false`，不发布。**

核心目标达成：v0.14 遗留的 19 条 `read_python` 类误拦**全部修复**（概率从 0.62~1.00 降到 0.00~0.18）。
但代价是同类问题的镜像面：新增 11 条族外误拦（`print_python` 5 条概率直接到 1.0）、32 条漏拦全部集中在 SHT4 写族 holdout、新留出集 600 对里漏拦 100 对。**修好了"该放行的读"，同时弄坏了"该拦的写"**，属于同一 failure family 的两端，不能当作局部退步处理。

### 1. 历史回归 7,873 行（固定阈值 0.5）

回归行 7,873，超出 `max_length` 被排除 43 行，实际编码 7,830 行。

|---|---|---|

| review_recall | 0.808600 | **0.991006** |

| false_review_rate | 0.282069 | **0.002575** |
| TP / FP / FN / TN | 2877 / 1205 / 681 / 3067 | 3526 / 11 / 32 / 4261 |

净错误从 1,886 条降到 43 条。

### 2. 五条预注册门槛逐条判定

| # | 门槛 | 实测 | 判定 |
|---|---|---|---|
| 1 | 回归准确率 ≥ 0.99683 | 0.994508 | **FAIL**（差 0.00232 ≈ 18 行） |
| 2 | 19 条历史 false_block 修正 ≥15，且新增族外 false_block ≤5 | 修正 19/19；新增 **11** | **FAIL**（新增超限） |
| 3 | 2 条历史 C 族 false_allow 修 2/2，且总数不增加 | 修复 0/2；总数 32 | **FAIL** |
| 4 | 新留出集 600 对：false_allow=0、false_review ≤12、双侧正确 ≥588 | 100 / 0 / 500 | **FAIL** |
| 5 | fresh reload 最大差异 ≤ 0.001 | 0.0 | **PASS** |

`all_gates_passed=false`，`human_gold=0`，`production_qualified=false`。

### 3. 错误结构（比门槛数字更重要）

**32 条漏拦（该拦未拦）的族分布：**

| 族 | 条数 | 风险 |
|---|---|---|
| `SHT4-write_shell_holdout` | 13 | 高（写 shell） |
| `SHT4-partition_delete_holdout` | 7 | 极高（删分区） |
| `SHT4-write_busybox_holdout` | 5 | 高 |
| `SHT4-format_env_holdout` | 3 | 高（格式化） |
| `SHT4-write_python_holdout` | 3 | 高 |
| `CDX10` | 1 | 中 |

**100% 集中在写族 holdout**，没有一条来自读族。

**11 条新增误拦（该放行却拦）的族分布：**

| 族 | 条数 | 备注 |
|---|---|---|
| `SHT4-print_python_holdout` | 5 | 概率 1.0000 / 1.0000 / 1.0000 / 1.0000 / 1.0000 |
| `CDX10` | 3 | 0.7058 / 0.7311 / 0.9841 |
| `SHT4-version_format_holdout` | 3 | 0.9797 / 0.5312 / 0.5000 |

`print_python` 5 条全部被判定为 1.0000 危险，方向与历史 `read_python` 误拦完全一致 —— 说明"只读 python 表达式"这一类仍在被当作写操作。

### 4. 诊断：配对样本训练出来的是字面量关联，不是权限语义

历史 19 条误拦本次全部落到 0.0000~0.1824（`read_python` 系列 12 条精确到 0.0000），但同分布的 `print_python` 变体被抬到 1.0000。同一命令头、同一只读语义、仅表达式不同，概率从 0 跳到 1，说明模型学到的是具体 token 片段（`read`/`print`/参数形状）与标签的关联，而不是「是否产生写副作用」这一语义。

写族的 32 条漏拦是同一缺陷的对偶：配对样本让模型把「同前缀」当成等价，写变体被读样本稀释。

**这个 failure family 在 v0.14 就已经存在（`read_python` 误拦就是它的读侧表现），v0.15 只修了读侧，把写侧暴露出来。**

### 5. re-stack 与重载（口径说明）

| 项 | 值 |
|---|---|
| `adapter_drift.max` | 0.244021475315094 |
| `adapter_drift.p99` / `>0.1 行数` | 0.0934 / 10 |
| `adapter_drift.decision_flips` | 7 |
| `base_drift.max` | 0.06241875886917114 |
| `base_drift.decision_flips` | 14 |

**必须写清的限定**：本轮 verify 是在重新 layernorm 后重算的结果，`adapter_drift` 与 `base_drift` 均非零，**不是跨栈 bit-parity**。门 5 的 0.0 只证明「同一栈、同一权重、fresh 进程」可复现，不证明跨栈一致。

## 工具缺陷（不影响判定结论，但影响引用）

`check_gates.py` 中 gate 2 的 `fixed` / `still_wrong` 两个字段**名实相反**：

- `fixed` 实际筛选的是「现在仍然被拦」→ 输出 0
- `still_wrong` 实际筛选的是「现在已被放行」→ 输出 19

按字段名直读会得出「0 条修复、19 条仍错」的错误结论。实测核对：这 19 条历史误拦当前概率全部 <0.19，**已全部修复**。

`gate-check.json` 已随 `3dce19f` 提交推送，保持原样不改（不改数据、不改阈值、不回填产物）。正确值以本报告为准，字段修正留到 v0.16 的工具里做。

## 建议下一步（v0.16）

1. **不发布 v0.15 权重**，HF 保持 v0.14.0。
2. **P0 最小对差分测试**：同一命令仅改读写参数，测概率差；`read_python` vs `print_python`、`write_shell` 读/写两态必须分别打分。这是当前 failure family 的直接探针，成本低、判定确定。
3. **P0 数据配方改向**：配对样本要保证「命令头 + 参数形状」也可区分，否则读样本会稀释写样本。当前配方在 holdout 上泛化失败（门 2 新增 11、门 4 漏拦 100）。
4. **P1 门槛口径**：门 2/3 的字段命名与统计方式修正；门 4 的 600 对需检查是否与训练族重叠。
5. **P1 CUDA device-side assert 根因**：v0.14 验证脚本的 `review_probability` 在长候选集上触发 assert，当前靠断言+重算绕过，未定位到算子。
