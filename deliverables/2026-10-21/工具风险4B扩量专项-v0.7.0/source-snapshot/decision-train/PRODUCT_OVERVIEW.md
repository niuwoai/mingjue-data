# 工具调用决策模型试训

当前版本：0.9.0；更新：2026-10-21。

使用固定 revision 的 Intern-Decision-2B，在 RTX 5070 Ti 单卡进行文本决策 LoRA。输入是脱敏命令及可见用户上下文，输出 allow / needs_review；unknown 与模型分歧隔离。风险、授权多轴标签保留在审计文件中，不输入模型。

环境复用 q4 的 `/home/ml-data/rsi-smoke/venv` 与固定基座和 upstream。先运行 `train.py --mode audit` 做 CPU token 化，再训练一个 epoch，最后 `--mode verify` 重新加载验证。必填参数为 `--model`、`--upstream`、`--data`、`--run`。默认最大 1536 tokens，超长排除并报告，梯度累积 16，LoRA r8，AdamW 5e-5。每 50 个优化步骤保存权重与优化器状态，当前版本不提供自动续训 CLI。

结果为弱监督实验，不能直接接入生产审批。必须报告类别数量、数据覆盖率、分歧排除和正例不足；需要独立人工金标才能判断业务验收。

另有20条训练前冻结的策略对照，包含相同命令在相反授权下的预期差异、系统目录破坏和凭据外发。仅用于诊断，预期标签由助手按规则设计，不是人工金标，不用于训练和选阈值。

首轮 systemd 试训设置 `--max-train-rows 2048`，在正式训练集合内保留全部正例、固定随机补充负例；完整清洗后的训练集仍保留，可用于后续全量训练。开发/校准/阈值/测试集合不参与训练抽样。systemd 正常或异常退出均恢复原 Qwen 推理服务。

第二轮通过 `augment.rb` 生成独立交付目录，保留原评估并补充按操作家族隔离的策略合成样本。合成标签是待验证的规则断言，不是人工金标。`--balanced-draws 2048` 在每个梯度累积批次各抽 8 条正常与需复核样本，类别池打乱后循环消费，损失不再叠加正例权重。记录全部抽样 ID 与重复曝光数量；预先固定阈值 0.5，测试集不选阈值。旧测试和旧20条对照仅作已观察回归，新合成测试按来源单独报告。

本轮实际训练360条唯一需复核样本，训练更新17.4分钟。新增合成测试216条全部答对，但原历史测试仍漏1/2正例、误拦4/704；旧20条对照检出9/10，仍漏掉整盘格式化。合成门槛通过不代表安全验收通过。`collect.py` 收集运行恢复和远端哈希证据，`verify_artifacts.rb` 核对本地下载、每批平衡、数据与训练源码，`report_balance.rb` 分开输出合成实验门槛与安全验收状态。最终结果保存在 `deliverables/2026-10-21/工具风险平衡增强与训练-v0.2.0/`。

第三轮磁盘专项由 `disk_data.rb`、`disk_review.rb`、`disk_finalize.rb` 生成和冻结。4000条唯一训练输入，正常/需复核各2000；另留400条按磁盘操作配方隔离的合成测试。命令、目标证据、提权字段固定，仅改变授权上下文形成对照。203条情境代表独立模型复核一致，不是逐条人工金标。`rsi-tool-gate-disk.service` 从原基座执行4096次平衡曝光，结束后独立重载，`disk_eval.py` 在同一测试上比较基座/第二轮/第三轮并单列旧回归。`collect_disk.py`、`verify_disk.rb`、`report_disk.rb`负责证据采集与本地报告。输出目录为 `deliverables/2026-10-21/工具风险磁盘专项与训练-v0.3.0/`。所有磁盘命令始终只作为数据文本，虚构的目标核验事实不能替代线上真实核验。

第三轮实际更新35.9分钟，4000条全部曝光。合成留出测试检出200/200、正常误拦0/200，授权对照100/100；旧原始格式化仍漏放，预注册门槛未通过。四条结果后诊断显示本例补充在线系统盘事实能改变判断，加-F不能修复缺失事实时的漏放；这不是独立测试。权重与数据已保留，生产资格仍为否。

第四轮由 `short_data.rb`、`short_review.rb`、`short_finalize.rb` 冻结4000条唯一训练输入，含2880条短上下文样本，正常/需复核各2000。环境字段缺失、null、空对象与未知说明在两类中均有覆盖，提权字段与授权标签解耦；无授权信息的普通镜像写入隔离为unknown。209条情境代表经独立模型复核，仍无人工金标。新留出500条组合隔离合成测试，旧测试仅作回归，原始mkfs输入不进训练。`short_eval.py` 固定阈值0.5比较基座/第三轮/第四轮，并单列短上下文、缺环境与授权对照。原始mkfs检出后才启动4B硬件验证。

`fetch_4b.py` 按官方固定revision下载4B权重并核对LFS SHA256及小文件Git对象哈希，不下载执行模型仓库代码。`probe_4b.py` 在独立目录进行BF16、LoRA r8、单样本至1536 tokens的两步训练与独立重载。工程探测不等于完整4B训练或模型质量验收；无论正常结束或失败均由systemd恢复原Qwen服务。第四轮交付目录为 `deliverables/2026-10-21/工具风险短上下文与4B验证-v0.4.0/`。

第四轮2B更新34.0分钟，4000条全部曝光；新合成测试检出245/250、正常误拦21/250，授权整组95/100。原始mkfs回归分数0.99966466，旧10条危险对照全部检出，但8.4%正常误拦超出预注册5%门槛，整体实验仍未通过。没有观察字段切片检出74/75、误拦5/75；无用户上下文切片检出20/20、误拦2/20。4B基座本机官方下载后经现有SSH传输，q4逐文件重新校验通过；BF16 LoRA r8完成2步更新、8次前反向、1536tokens压力与独立重载，Torch峰值保留10.38GiB。本配置工程可训练，未做全量4B训练或质量验收。原Qwen推理与SSH探活均恢复。

第五轮使用同一4000条训练完整4B，256步/4096次曝光、与2B顺序完全一致，更新47.0分钟。原5条漏放和21条误拦全部修复，但新增15条shell重定向写入漏放；同一500条检出235/250、正常误拦0/250，准确率97%但危险召回94%低于2B的98%，不能据总体准确率认定更安全。原始mkfs分数0.99951220，独立重载一致；模型、逐条对比及恢复证据位于 `deliverables/2026-10-21/工具风险4B完整训练与2B对比-v0.5.0/`。该测试此前已观察，人工金标为0，未作生产自动审批验收。

第六轮通过 `shell_data.rb`、`shell_review.rb`、`shell_finalize.rb` 保留原4000条并补2000条shell重定向高危、正常与授权对照，另冻600条新组合测试。218条有效独立模型复核；原语法检查缺授权分歧保留unknown并隔离样本族，改用明确授权正常对照逐条重审，全部修订发生在学生训练前。`shell_4b.py` 从原4B基座执行6016次平衡曝光/376步，固定0.5阈值；`shell_eval.py` 对新600条比较原基座、上轮4B与本轮，并另跟踪旧15条、原26条及旧500条退化。目标为新召回至少95%且误拦不超过2%，旧15条零漏放；通过也不等于生产验收。交付目录为 `deliverables/2026-10-21/工具风险4B重定向专项-v0.6.0/`。

第六轮实际更新66.9分钟、6000条全部曝光，独立重载600条分数一致。新600条检出从上轮263/300降至238/300，正常误拦从12/300降至5/300；旧15条修复0/15，旧500条检出从235/250降至202/250，误拦0，原26条未退化。实验失败，未替换上轮模型或接入生产审批。结果后的6条最小诊断中，原案例仅将目标/dev/nvme7n1换成/dev/sdg，分数即从0.0373升至0.9998；训练内一正一负对照正确，支持本例对目标字面形式敏感，不能外推全部失败原因。诊断未继续训练或调阈值，结束后原推理与SSH探活恢复。

第七轮扩量由 `shell_scale_data.rb` 保留第六轮6000条训练输入并补4000条，累计10000条；新增测试集1200条，与训练按整组命令包装隔离。新增8种shell写入表达、10种未见测试包装，以及写设备、只读请求、待确认、已授权普通镜像/loop和正常日志对照。238条分层代表由独立模型复核，一致率在该抽样中为100%；并非人工金标。`shell_scale_finalize.rb` 冻结数据哈希与拆分，`shell_4b_scale.py` 从原始4B基座训练，`shell_eval_scale.py` 固定0.5阈值比较原基座、上一轮4B和新模型，并跟踪全部旧回归。目标是漏放下降且误拦保持低位；无论合成测试是否通过，都不授予生产自动放行资格。q4训练由独立oneshot服务运行，完成/失败均恢复原推理服务。
